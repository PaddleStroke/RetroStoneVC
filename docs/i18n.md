# Translated games (i18n)

The RetroStone VC games show their texts in the player's language: the 22 languages of RetroStoneOS's menu
(`frontend/po` there): English, and `cs da de el es fi fr id it ja ko nb nl pl pt_BR pt_PT ru sv tr uk zh_CN`.
**Every translation except English was made by an AI (Claude) and has not been reviewed by native speakers yet**:
each file says so in its first line, and a review is very welcome (replace that line with the reviewer's name).

The game names stay as they are in every language (they are brand names). Everything else the player reads is
translated: the house kit's words (the title prompt, the join line, BEST, the game-over panel, the results, PAUSED...)
and each game's own (its title verb, hints, HUD labels, messages, biome and medal names).

## 1. Strings

### Files
- `games/common/strings/<lang>.txt`: the house kit's strings (about 45).
- `games/<game>/strings/<lang>.txt`: the game's own (1 to 15).
- `en.txt` is the source; a key missing from a translation shows the English.

```
#. A note for translators about the next key: where it shows; "max N" = its room in 8-px columns.
#. max 34
PRESS_TO = PRESS A TO %s
FULL[one] = %d PLAYER - B: LEAVE
FULL[other] = %d PLAYERS - B: LEAVE
```
- `KEY = TEXT`: the text runs to the end of the line (UTF-8); `"..."` keeps spaces at its ends.
- `%d`, `%s`, `%02d`... are kept, the same kinds and count; a translation may reorder them with numbered conversions
  (`%2$s %1$s`, all numbered then). `A`, `B`, `L/R`, `START`, `SELECT` are pad buttons: their letters stay.
  `{ } ^ ~` are drawn as arrows (left, right, up, down).
- Plurals: `KEY[one]`, `KEY[few]`, `KEY[many]`, `KEY[other]`, the forms the language needs: one and other (most),
  cs one/few/other, pl, ru, uk one/few/many, ja, ko, zh_CN, id other only (the rules of `rs_plural()`, gettext's).
- Capitals: the house font has capitals only, so the tool writes capitals (Turkish i becomes İ, Greek capitals lose
  their accents, German ß becomes SS); translators may write either.
- Numbers are plain digits (the big score digits are sprites), no thousands separator.
- The room: `max N` in the note, else the English length. `tools/i18n_build.py --check` lists the translations longer
  than their room; the language test (section 5) is what really decides: it fails when a text leaves its panel or the
  screen.

Conventions kept across the files: "tu" in French (as RetroStoneOS), "du" in German, the informal "you" everywhere it
exists; the player tag is J1 in French, Spanish and Portuguese, G1 in Italian, 1P in Japanese, Korean and Chinese,
P1 elsewhere; the title verb takes the form the language's `PRESS_TO` needs (infinitive in most languages; Finnish and
Czech imperative, "PAINA A JA UI"; Greek subjunctive after "ΓΙΑ ΝΑ"; Turkish infinitive before "İÇİN"; Japanese
dictionary form; a noun in Korean).

### The tool
`tools/i18n_build.py` (Python 3, no dependency):

| Command | What it does |
|---|---|
| `--game G --out build/gen/G` | `game_text.c` and `game_text.h`: the kit's and the game's tables in the 22 languages, the wide glyphs they use; run by the Makefile for every house-UI game and every game with a `strings/` folder |
| `--kit-header` | rewrites `games/common/src/house_text.h` (the kit's string ids, committed: `house_ui.c` is compiled once for all games) after a change of the kit's `en.txt` |
| `--check [G...]` | the keys, the conversions, the plural forms, every character in a font, the rooms (part of `make check`) |
| `--fonts [--unifont F]` | rebuilds `games/common/fonts/unifont-subset.hex`: the wide glyphs (CJK) all the games' strings use, from the full Unifont `.hex` (SDL2's source has it: `test/unifont-13.0.06.hex`; the tool also looks in `build/deps/SDL2-*` and `$UNIFONT_HEX`) |
| `--report` | the coverage, languages x games, as a Markdown table |

The generated table is `const` data: one array of UTF-8 pointers per language (`NULL` where not translated); the
generated file registers its pack with the runtime before `main()` (a constructor), so the kit finds the strings
without the game doing anything.

## 2. The runtime API (`sdk/include/rs_i18n.h`)

| Call | |
|---|---|
| `rs_lang()` | the player's language, `RS_LANG_EN` .. `RS_LANG_ZH_CN` (fixed for a run, like the screen width) |
| `rs_lang_code(l)`, `rs_lang_find("pt-BR")`, `rs_lang_from_retro(v)` | codes, any locale name, libretro's enum |
| `TR(KEY)`, `TRN(KEY, n)` | (`game_text.h`) a game string, a plural; the English when not translated |
| `HTR(KEY)`, `HTRN(KEY, n)` | (`house_ui.h`) a kit string |
| `rs_strf(buf, size, fmt, ...)` | `snprintf` for translated formats: `%d %i %u %c %s %%`, flags, width, and `%2$s` reordering |
| `rs_text_cols(s)`, `hu_width(s, big)` | the text's width in columns (a CJK character: 2) |
| `rs_utf8_next(&s)` | the next code point |

A game's code becomes, for example:
```c
#include "game_text.h"
hu_title_cfg tc = {START_INPUTS, MAX_PLAYERS, TR(VERB), NULL, 0};        /* PRESS A TO <VERB>, translated */
hu_banner(4, HTR(GAME_OVER));
rs_strf(s, sizeof s, TR(HUD_FLIES_PAD), flies, seconds);                 /* "FLIES %d - PAD %dS" */
hu_text(hu_center(s, 0), 6, s);
```
Every `hu_*` text call takes UTF-8. Layouts must adapt: widths from `hu_width()`, not `strlen()`; centred or aligned
text, panels sized to their text, UTF-8 buffers (up to 4 bytes per character). The kit's own panels adapt (the
game-over panel widens for long labels, a banner grows with its title and takes one more row for accents).
`hu_tall(s)` says whether a text takes the row above it (accents, CJK): a game can then spread packed rows (several
titles do); `hu_gameover_note(s)` adds a line at the foot of the game-over panel. A 2x word wider than a split view
(Turkish DURAKLATILDI) falls back to 1x in the games that need it. The kit's "off the screen" check knows the 40-column
UI area (and the widescreen margins): split-screen games keep their UI text in those columns.

## 3. The player's language

| Platform | Where it comes from |
|---|---|
| RetroStoneOS (libretro) | the core option **Language** (`rsvc_language`: Auto or one of the 22); Auto asks the variable `rsos_language` that the RetroStoneOS host gives every core (the user's menu language, `fr`, `pt_BR`, `da`, `nb`...: all 22), then `RETRO_ENVIRONMENT_GET_LANGUAGE`, then English. Read when the game starts: a change applies at the next start or reset |
| RetroArch | the same: Auto = RetroArch's user language (`GET_LANGUAGE`) |
| Windows, Linux (SDL2 runner) | `--lang fr`, else `RS_LANG=fr`, else the system's: `SDL_GetPreferredLocales()` (SDL 2.0.14+), the first locale that is one of ours |
| Android | the embedding host calls `rs_host_set_lang(rs_lang_find(locale))` before `rs_host_init()` with the system locale (Java `LocaleList`, or SDL's preferred locales when the app is SDL-based) |
| Headless runner, tests | `--lang fr`, `RS_LANG=fr` or `--opt lang=fr`; never the system's (the runs stay the same everywhere) |

Locale mapping (`rs_lang_find`): `pt-BR` is pt_BR, any other `pt` pt_PT; `zh`, `zh-Hans`, `zh-CN`, `zh-SG` zh_CN
(`zh-Hant`, `zh-TW`, `zh-HK` are not ours: the next preferred locale, else English); `no`, `nn`, `nb` nb; `in` id;
`fr-CA` fr and so on; anything else English.

libretro's language enum has no Danish (and older `libretro.h` files no Norwegian): libretro frontends pass Danish
as English. RetroStoneOS also answers `GET_VARIABLE("rsos_language")` with the code (`da`), so all 22 work there; in
RetroArch a Danish player picks "Dansk" in the core option.

Save states load in any language (the language is a setting of the frontend, like the width): text on screen
from the state stays until it is drawn again.

## 4. Fonts

**The house font**, 5x7 capitals in 8x8 tiles (`sdk/tools/gen_font.py`), now also draws, in the same pixel style
(`sdk/tools/gen_font_ext.py`, original, MIT):
- Latin-1 and Latin Extended-A: every accented capital is the ASCII letter plus a **mark** (acute, grave, circumflex,
  tilde, diaeresis, ring, caron, breve, dot, double acute) drawn in the bottom rows of the tile **above** the letter,
  so the letter stays exactly the same; the marks below (cedilla, ogonek) are in the letter's row 7. Letters that are
  not a base plus a mark are drawn whole: Æ Ø Œ Ł Đ ¡ ¿ º ª « » ×.
- Cyrillic (Russian, Ukrainian: Й is И plus a breve, Ё Ї plus a diaeresis) and Greek capitals, the Latin shapes
  reused where they are the same letter.
That covers fr de es it pt pl cs tr sv da nb fi nl id, ru uk and el. `sdk/tests/test_i18n.c` checks it.

**Japanese, Chinese and Korean** use **GNU Unifont 13.0.06** 16x16 glyphs (SIL OFL 1.1; THIRD_PARTY.md), a pixel font
that matches the house style well at 2x the house font's height. Only the characters the strings use are kept:
`games/common/fonts/unifont-subset.hex` (all games: 563 glyphs), and each game embeds only its own (about 200-250
glyphs, 32 bytes each: 6-8 KB of ROM). A wide character takes 2 columns and 2 rows (the row above the
text, like accents).

**VRAM.** English never writes a tile more than before. Other languages draw what is not ASCII into a **pool of
tiles** of the UI layer (`hu_config.ext_tile`, `ext_count`: 640..767 by default, 128 tiles = 4 KiB, after the logo's
320..639; games whose next layer starts at 640 move it), filled as text is shown: each slot holds one tile (a letter,
an accent over the blank or over a panel's fill, a half or a quarter of a wide glyph); `hu_clear()` empties it, and a
full pool frees the tiles the UI layer no longer shows. Peaks measured by the language test of the 20 games (the log's
`[i18n] glyph pool` lines, in steps of 16): Latin languages under 16 tiles, Russian 32-48, Greek and Ukrainian 48,
Japanese, Chinese and Korean 48-128 (a CJK character costs 4 tiles: 2 halves and the 2 tiles above), Biscuit Bandit's
three CJK hint lines 160. So: 0 in English, at most +4 KiB (128 tiles) against the 64 KiB guideline in most games;
Biscuit Bandit gives the pool 256 tiles (+8 KiB), Pogo Mamie and Nutty Branch 160 at 480..639 (their next layer starts
at 640), Blueberry Tumble moved its BG4 from 640 to 1024. The house font's ASCII tiles stay where they were.

## 5. Tests

- `make check` (and every game's check): `build/host/test_i18n` (locales, libretro's enum, plurals, positional
  formats, UTF-8, the extended font) and `tools/i18n_build.py --check`.
- `test_libretro` checks that the core declares the Language option and asks `rsos_language` then `GET_LANGUAGE`.
- RetroStoneOS: its launch test checks the host's answers (`GET_LANGUAGE` and `rsos_language` for seven settings).
- **The language test**, `tools/i18n_test.sh <game>_headless <game> <out> <widths>` (in every game's check): runs the
  screens listed in `games/<game>/tests/i18n_runs.txt` (the title alone and with 2 and 4 players, play with 1 and 4
  players, pause, the game over, the 4-player results, the game's own messages) in the 22 languages at 320 and, for the
  widescreen games, at 427 and 520 columns, in parallel (a few seconds per game). The kit logs every layout error once,
  `i18n: <what> at x,y (<lang>, <width> px): "<text>"`: text off the screen, text over a panel's edge, an accent or a
  tall glyph over other text, a character no font has, a full glyph pool, a banner wider than the screen. Any of them,
  or a failing run, fails the test. `SHOTS=1` keeps the screenshots, `LANGS="fr ja"` limits the languages.
- English stays byte-identical: the games' screenshot tests give the same pictures as before (the ASCII path of the
  kit is unchanged), compared screen by screen against the code before the change for all 20 games (at 320, 427 and
  520 for the widescreen ones). Intended English changes: Duck Parade's photo panel now fits "2 DUCKLINGS HOME!"
  (it ran over its edge) and says "1 DUCKLING HOME!" for one; Pancake Tower says "1 PANCAKE" (not "1 PANCAKES").
- Screenshots: `docs/i18n/` (Mole Marbles in French, German, Russian, Japanese and Chinese).

## 6. Adopting it in another game (Bomber Mole, a new game)

A house-UI game already gets the kit's translations as soon as it is built (the Makefile generates `game_text.c` for
it). Then:
1. Write `games/<game>/strings/en.txt` with every text the game draws itself (format above; a note with `max N` for
   each, measured on the layout). Not the game's name, not log lines, not debug text.
2. In the code: `#include "game_text.h"`; replace each literal by `TR(KEY)` (or `HTR(KEY)` for the kit's words:
   GAME_OVER, PAUSED, BACK_TITLE "A: TITLE", BACK_MENU, NEW_BEST_EXCL, BEST_N, METRES_N, SCORE, PLAYER_TAG...),
   formats through `rs_strf`, plurals `TRN`. Make the layouts adapt (section 2) and keep the row above each text line
   free (accents, CJK).
3. Translations: one `<lang>.txt` per language (an AI draft is fine; mark it "Translated by AI, review welcome").
   `python3 tools/i18n_build.py --check <game>`, then `--fonts` when the Japanese, Chinese or Korean texts use new
   characters (commit the `.hex`).
4. `games/<game>/tests/i18n_runs.txt` (copy Mole Marbles'), and in the game's check target:
   `bash tools/i18n_test.sh build/host/<game>_headless <game> build/<game>-i18n $(if $(WIDESCREEN_<game>),320 $(WIDTHS),320)`.
   If `game.mk` lists objects itself with `build/gen/<game>/assets.c`, add `build/gen/<game>/game_text.c`.
5. VRAM: leave 96-128 tiles of the UI layer for the glyph pool (`hc.ext_tile`, `hc.ext_count`).

**Bomber Mole** does not use the house kit: it draws with the SDK's `rs_text()`, which stays ASCII. It adopts the
system in two parts: (1) steps 1-3 above (its strings and `TR()`; add `HOUSE_UI`-free generation by giving it a
`strings/` folder: the Makefile then builds `game_text.c` for it too); (2) a text path for UTF-8: either draw its
texts with the kit's text functions on its UI layer (`hu_init` with `obj_tile = -1` and `logo_tile = -1` costs only
the kit's font tiles), or port the kit's `put_text()` (house_ui.c, "translated text": the pool, the marks above, the
wide glyphs) to its own text layer. Its HUD rows are packed: give accents the row above.
